## Introduction

**S3 Buckets** gives you S3 compatible object storage directly in the console. It uses the standard S3 API, so any existing S3 client (AWS CLI, rclone, Boto3, Cyberduck, and more) works with Hippius without modification.

From this page you can create and manage buckets, upload and download objects, and generate credentials for your S3 clients.

Reach S3 Buckets from the sidebar at <BgStyledIconWithText text="S3" icon="SidebarStorage" /> → <BgStyledIconWithText text="S3 Buckets" icon="Database" />.

For a full reference of supported S3 API operations, see [S3 Compatibility](/storage/s3/compatibility). First upload: [S3 Quickstart](/use/quickstart). Sharing and ACLs: [Advanced Usage](/storage/s3/advanced).

## Master Tokens

Before you can create buckets or connect any S3 client, you need a **master token**. This is your top level S3 credential. It has access to every bucket and every operation on your account.

The first time you open the S3 page, you'll be prompted to create one.

### Creating a Master Token

<Ordered>
  <li>Click <BgStyledText>+ Create Master Token</BgStyledText> in the page header (or click the prompt in the empty buckets table).</li>
  <li>Enter a <strong>Token Name</strong> to help you identify it later (e.g. <em>"Production Token"</em>).</li>
  <li>Pick an <strong>expiry</strong>: <strong>7 days</strong>, <strong>30 days</strong>, <strong>1 year</strong>, or a <strong>custom date</strong>.</li>
  <li>Click <BgStyledText>Create Master Token</BgStyledText>.</li>
  <li>The dialog shows your new <strong>access key</strong> and <strong>secret key</strong>. Copy both now using the copy buttons.</li>
  <li>Click <BgStyledText>Done</BgStyledText> to close.</li>
</Ordered>

<Screenshot src="/img/console/s3/create-master-token.png" alt="Create master token dialog" dark />

:::warning Save your secret key immediately
Once you close this dialog, the **secret key is gone forever**. If you lose it, you'll need to revoke the token and create a new one. The access key remains visible, but the secret is never shown again.
:::

### Managing Master Tokens

Click <BgStyledText>Manage</BgStyledText> in the bucket browser toolbar to open the tokens page, then pick the <strong>Master Tokens</strong> tab. From there you can:

<Unordered>
  <li>See all your master tokens with their access keys, creation dates, and expiry dates.</li>
  <li><strong>Rotate</strong> a token: a new secret is issued and the old one stops working.</li>
  <li><strong>Revoke</strong> a token immediately. Any client using it will start getting auth errors right away.</li>
  <li>Create additional master tokens with <BgStyledText>+ New Master Token</BgStyledText>.</li>
</Unordered>

<Screenshot src="/img/console/s3/master-tokens.png" alt="Master tokens management" dark />

## Sub Tokens

A **sub token** is a scoped credential derived from a master token. Use sub tokens to share access without handing out your master credentials.

| Why use sub tokens | Example |
|---|---|
| **Per bucket access** | A backup script that only needs one specific bucket. |
| **Read only** | A CDN that should never be able to delete or overwrite. |
| **Time limited** | A vendor access that expires after one week. |
| **Easy revocation** | Revoke a sub token without touching the master. |

### Creating a Sub Token

<Ordered>
  <li>Click <BgStyledText>Manage</BgStyledText> in the bucket browser toolbar to open the tokens page, and stay on the <strong>Sub Tokens</strong> tab.</li>
  <li>Click <BgStyledText>+ New Token</BgStyledText>.</li>
  <li>Enter a <strong>Token Name</strong>: a label so you remember what this token is for (e.g. <em>"Production backups"</em>).</li>
  <li>Choose <strong>Permissions</strong>: <em>Object Read Only</em> or <em>Object Read &amp; Write</em>.</li>
  <li>Pick the <strong>Bucket</strong> scope: all buckets, or specific ones.</li>
  <li>Set <strong>Activate After</strong> (Immediately, 1 day, 7 days, 30 days, or Custom) and <strong>Token Lifespan</strong> (Forever, 7 days, 30 days, 1 year, or Custom).</li>
  <li>Click <BgStyledText>Create Sub Token</BgStyledText>.</li>
  <li>Copy the access key and secret key before closing the dialog.</li>
</Ordered>

<Screenshot src="/img/console/s3/create-sub-token.png" alt="Create sub-token dialog" dark />

### Managing Sub Tokens

Each sub token row shows its name, access key, bucket coverage, permission scope, and expiry date. The action menu on each row lets you:

<Unordered>
  <li><BgStyledText>Rotate</BgStyledText>: issue a new secret for the same token. The old secret stops working.</li>
  <li><BgStyledText>Revoke</BgStyledText>: invalidate the sub token immediately.</li>
</Unordered>

The secret key is never shown again after creation.

<Screenshot src="/img/console/s3/sub-tokens.png" alt="Sub-tokens management" dark />

## Buckets

### Creating a Bucket

<Ordered>
  <li>With an active master token, click <BgStyledText>+ Create Bucket</BgStyledText> in the page header.</li>
  <li>Enter a <strong>bucket name</strong>. Names must be lowercase letters, numbers, and dashes only, between 3 and 63 characters, and must start and end with a letter or number.</li>
  <li>Click <BgStyledText>Create Bucket</BgStyledText>.</li>
</Ordered>

The new bucket appears at the top of the list. Click its row to open it.

<Screenshot src="/img/console/s3/create-bucket.png" alt="Create bucket dialog" dark />

### Bucket Actions

Each bucket row has an action menu (three dots):

<Unordered>
  <li><BgStyledText>Browse Files</BgStyledText>: open the bucket. Same as clicking the row.</li>
  <li><BgStyledText>Copy URL</BgStyledText>: greyed out, marked Coming Soon.</li>
  <li><BgStyledText>Delete Bucket</BgStyledText>: permanently delete the bucket. The bucket must be empty first. The dialog will block you if it still contains objects.</li>
</Unordered>

<Screenshot src="/img/console/s3/bucket-actions.png" alt="Bucket actions menu" dark />

## Inside a Bucket

Clicking a bucket opens the bucket browser, where you can manage all its objects.

<Screenshot src="/img/console/s3/bucket-detail.png" alt="Bucket detail page" dark />

### Folders

S3 buckets are flat by design. There are no real folders, only object keys that contain slashes. The console presents these as folders for a familiar browsing experience.

To create a folder:

<Ordered>
  <li>Click <BgStyledText>Add Folder</BgStyledText> in the bucket toolbar.</li>
  <li>Enter the folder name. It's created relative to your current location in the breadcrumb.</li>
  <li>Click <BgStyledText>Create Folder</BgStyledText>.</li>
</Ordered>

A zero byte placeholder object appears immediately. It's automatically removed when you upload a real object into the folder.

<Screenshot src="/img/console/s3/create-folder.png" alt="Create folder dialog" dark />

### Uploading Objects

Click <BgStyledText>+ Upload Object</BgStyledText> to open the upload dialog. The destination is always the folder shown in the current breadcrumb. Navigate to the right folder first, then upload.

Each file must be under **100 MB**. For larger files, use an S3 client with multipart upload support. See [Connecting an S3 Client](#connecting-an-s3-client) below.

<Screenshot src="/img/console/s3/upload-object.png" alt="Upload to bucket dialog" dark />

### Browsing and Previewing Objects

Click any object to preview it. Images, videos, PDFs, Word documents (DOCX), spreadsheets (XLSX, CSV), presentations (PPTX), Markdown, HTML, plain text, and JSON files open inline in the browser, using the same viewer as [Drive](/use/console/drive#previewing-files). For all other file types, use the action menu to download the file instead.

Use the search box to filter objects by name in the current folder. Click the refresh icon to reload the listing after another client has added objects in the background.

### Object Actions

Each object has an action menu (three dots):

<Unordered>
  <li><BgStyledText>Download</BgStyledText>: save the object to your device.</li>
  <li><BgStyledText>Share via Link</BgStyledText>: create a presigned link for a private object, or copy the permanent URL of a public one.</li>
  <li><BgStyledText>View on Hipstats</BgStyledText>: open the object's file tracker page on hipstats.com, once it has an Arion hash.</li>
  <li><BgStyledText>Object Details</BgStyledText>: open the details panel (file name, file type, date, size, Arion hash).</li>
  <li><BgStyledText>Delete Object</BgStyledText>: permanently delete the object.</li>
</Unordered>

### Selecting and Deleting Multiple Objects

Tick row checkboxes (or the header checkbox to select all on the page) to enter selection mode. The **Selection Action Bar** at the bottom lets you bulk delete or bulk download the selected objects.

<Screenshot src="/img/console/s3/selection-bar.png" alt="S3 selection action bar" dark />

## Connecting an S3 Client

Once you have a master or sub token, configure any S3 compatible client with these settings:

| Setting | Value |
|---|---|
| **Endpoint** | <code>https://s3.hippius.com</code> (see <a href="/use/quickstart#connection-details">Getting Started</a>). |
| **Region** | <code>decentralized</code>. |
| **Access key** | From your master or sub token. |
| **Secret key** | The secret you copied at creation time. |
| **Path style addressing** | Required. Hippius does not support virtual hosted style URLs. |

## Paying for S3

S3 starts on **pay as you go**: you pay $6 per TB per month for what you store, charged hourly from your account balance, with no cap.

If you store a lot, a monthly **S3 plan** covers a block of storage for a flat price and is cheaper per TB. Click <BgStyledText>Upgrade</BgStyledText> at the top of the S3 page to compare them. On a plan, uploads pause at your cap rather than costing more.

If your balance runs out on pay as you go, S3 turns **read only** after 7 days, **suspended** 7 days later, and the data is **deleted** 23 days after that (37 days in total), with a final notice a week before. Any top up that covers your usage lifts it. See [Billing → S3 plans and pay as you go](/use/console/billing#s3-plans-and-pay-as-you-go).

## Limits

| Limit | Value |
|---|---|
| **Max single object upload via console** | **100 MB** |
| **Max bucket name length** | 63 characters |
