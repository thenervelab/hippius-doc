# Python SDK and CLI

`hippius-drive` is the public Python SDK and command line for Drive. It does what the apps do for files, from a script: encrypt on your machine, upload, download, list, search, rename, delete, share. The server only ever holds ciphertext and cannot read your data.

It is pure Python, MIT licensed, and the crypto is readable in the repository rather than shipped as a binary. Python 3.10 to 3.13.

```bash
pip install hippius-drive
```

Source and issues: [github.com/thenervelab/hippius-drive-sdk](https://github.com/thenervelab/hippius-drive-sdk).

:::info What it does not do yet
There is **no sync engine** in v1. The SDK will not watch a folder and keep it in step with Drive the way the desktop app does. It is for scripts you run: a nightly backup job, a pipeline that drops results into Drive, an export. If you want folders that stay in sync on their own, use the [desktop app](/use/desktop/drive).
:::

## What you need

| | Where it comes from |
|---|---|
| **API token** | [Settings](/use/console/settings) in the console |
| **Account address** | The account the token belongs to, shown in the console |
| **Recovery phrase** | Generated by the SDK on your machine, or the one you already use in the apps. It never leaves your machine. |

The token and the address go together: the server resolves the token to an address and refuses any request that names a different one. Getting this wrong shows up as a `403` on the first request. The phrase is separate, and it is the only thing that can decrypt your files.

## From the command line

```bash
hippius-drive init          # generates a phrase, stores it encrypted, prints it once
hippius-drive whoami        # checks token, account and folder
hippius-drive register      # registers the folder on the server (safe to repeat)
hippius-drive put ./report.pdf work/report.pdf
hippius-drive ls work
hippius-drive get work/report.pdf ./out.pdf
```

`init` prints the phrase **once**. Store it offline. To reuse a phrase you already have, run `hippius-drive init --mnemonic "word word ..."` instead; it is not echoed.

Configuration is read from flags, then environment variables (`HIPPIUS_TOKEN`, `HIPPIUS_ACCOUNT_SS58`, `HIPPIUS_PASSWORD`), then `~/.config/hippius-drive/config.toml`. In CI, where there is no terminal, set `HIPPIUS_PASSWORD` or the command exits with an error naming it rather than waiting on stdin.

The full command list is in the repository: [docs/cli.md](https://github.com/thenervelab/hippius-drive-sdk/blob/main/docs/cli.md).

## From Python

```python
from pathlib import Path
from hippius_drive import Client, Identity

identity = Identity.from_master(master_phrase, "default", account_ss58=account)

with Client(token=token, identity=identity) as client:
    client.folders.register()
    client.files.put(Path("report.pdf"), "work/report.pdf")
    client.files.get(client.files.file_id("work/report.pdf"), Path("out.pdf"))
```

`"default"` is the folder label. The same label always addresses the same folder, which is how two machines reach the same files without coordinating. `AsyncClient` mirrors the same surface with `async` and `await`.

Uploads route by size on their own: small files go in one request, larger ones through a resumable chunked session. Downloads are written to a `.part` file and renamed into place only after the last piece authenticates, so a failed transfer never leaves a half-decrypted file behind.

The walkthrough, including updating a file with optimistic concurrency, listing, search and shares, is in [docs/quickstart.md](https://github.com/thenervelab/hippius-drive-sdk/blob/main/docs/quickstart.md).

## What is in v1

<Unordered>
  <li>Identity and folders</li>
  <li>Upload, single request or resumable chunked session</li>
  <li>Streaming download</li>
  <li>Listing, directory browse, cross-folder search (paged by the server: walk with <code>iter_browse()</code> and <code>iter_state()</code>)</li>
  <li>Account summary and quota pre-flight</li>
  <li>Rename and delete</li>
  <li>File shares and folder shares, which mint a console link whose fragment is the decryption key</li>
  <li>Shared drives: a second account joins a folder with its own token and receives that folder's key; the owner's phrase stays with the owner</li>
</Unordered>

## Not in v1

<Unordered>
  <li>The sync engine</li>
  <li>Recovery bindings and mnemonic-blob server endpoints</li>
  <li>Admin endpoints</li>
  <li>S3-gateway variants</li>
</Unordered>

## Security

The server stores ciphertext and never receives your recovery phrase or encryption key. It does see some metadata: file sizes, timestamps, and, when you send them, plaintext paths. What that does and does not protect is written out in [docs/security.md](https://github.com/thenervelab/hippius-drive-sdk/blob/main/docs/security.md).

:::danger Your recovery phrase is the only thing that can decrypt your files
Nobody can recover it for you, and changing it orphans everything already stored under it. Keep it offline.
:::
